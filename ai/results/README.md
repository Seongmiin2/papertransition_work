## 2. OCR 인식기

| 날짜 | 모델 | 평가 데이터 | 완전일치 | 편집 유사도 | 상태 |
|---|---|---|---:|---:|---|
| 2026-08-26 | 공식 pretrained | validation 2문서 | 84.09% | 97.26% | 기준선 |
| 2026-08-26 | 1차 fine-tune | test 2문서 | 96.44% | 98.87% | 실험 완료 |
| 2026-08-26 | v2 continued fine-tune | test 4문서, 2,921행 | 95.5701% | 98.1530% | 배포 중 |
| 2026-08-27 | v3 lr=1e-5 | 같은 test 4문서, 2,921행 | 95.5357% | 98.1052% | 배포 보류 |

배포 v2에 결속된 line crop 진단(분할 간 중복을 제거한 test 2,101행)은 CER 0.4862%, 완전일치 90.8139%다.
이 값은 줄 단위 인식만 재며 문서 검출, 읽기 순서, 표, 레이아웃은 포함하지 않는다.

1차와 v2는 데이터 분할이 달라 수치를 직접적인 하락으로 해석하지 않는다.
v2와 v3는 같은 test split 안에서의 상대 비교만 가능하다. 이 test 4문서 중
3문서가 v1 train에 사용된 문서이므로 두 수치 모두 독립 holdout 성능이나 제품
승격 근거로 사용할 수 없다. 당시 v3가 완전일치 한 줄과 편집 유사도 모두 낮아
runtime을 교체하지 않았다는 역사적 판단만 유효하다.

## 4. Model A 연구 실험

모두 연구용이며 사람 검증 정답이 아니라 기계 투영이나 기존 파이프라인과 비교한 진단값이다. 제품 승격 근거로 쓰지 않는다.

| 실험 | 날짜 | 핵심 지표 | 판정 |
|---|---|---|---|
| 줄 단위 오류 위험 모델 | 09-09 | 오류 recall 0.98에서 F1 0.174 (confidence만 쓴 기준선 0.237), ROC-AUC 0.789 | 기각 |
| 위험 점수 순위 결합 | 09-09 | F1 0.249 (기준선 0.237), ROC-AUC 0.821 | 배포 안 함, 새 분할에서 재검증할 가설 |

## 기록 방법

벤치마크 JSON을 기존 CSV 형식으로 추가할 때:

```powershell
python ai/results/record_metrics.py --report output/benchmarks/<run>/ocr_benchmark.json --component ocr --model-config-id <model-id> --notes "<decision context>"
```

같은 날짜·component·model·metric·split 조합은 중복 추가하지 않는다. 모델을 승격하거나 보류할 때는 수치뿐 아니라 판단 이유도 실험 JSON에 남긴다.
